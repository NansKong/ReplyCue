# Managed beta setup

The static website and managed gateway are separate Vercel projects. Use apps/website for the site and apps/gateway for the Node gateway. The Windows installer reads the same public configuration as the website. Leave the managed settings blank to keep the existing local-key development flow.

1. Create a dedicated Firebase beta project. Enable Email/Password Auth, email enumeration protection and an appropriate password policy. Add the website domain to Firebase Auth and create a Firestore database. Apply apps/gateway/firestore.rules to the dedicated project so only server credentials can access the ledger. Do not replace rules on a shared production database with this file.
2. Configure the gateway project with FIREBASE_SERVICE_ACCOUNT_JSON and dedicated GROQ_API_KEY and REPLICATE_API_TOKEN as server-only secrets. Use a limited service account that can read Auth users for revocation checks and transact against Firestore. Keep these credentials out of the repository, client config and installer.
3. The trial grants each verified account 3,600,000 ms of active session time. Firestore stores an email-based time ledger, so signing out or reinstalling cannot reset it. Start and Resume acquire a 30-second server lease, renewed every 10 seconds. Pause and End settle the elapsed time and release the lease. A disconnected client consumes at most the remainder of that lease. One active session per account is permitted. Accounts created before this change receive the full hour regardless of their earlier dollar allowance. TRIAL_LIMIT_MICROUSD is no longer read.
   AUDIO_RESERVE_MICROUSD and ANSWER_RESERVE_MICROUSD still record conservative provider spend per request. Set them to cover a 21-second Whisper Turbo request and a 32,000-byte prompt plus 2,048 Gemini 2.5 Flash output tokens. The answer reservation has a minimum of 25000 microdollars. Set BETA_LIMIT_MICROUSD only if a cumulative cost cap across all accounts is required. One USD is 1,000,000 microdollars.
4. Start with BETA_ALLOWED_EMAILS as a comma-separated invite list and BETA_ENABLED=false. Configure endpoint-level rate limits in the hosting platform to protect Firebase and hosting spend. Enable BETA_ENABLED=true only after testing with staging credentials and a small cap. Set independent provider-level spending limits where available. The Firestore cap bounds reserved Groq and Replicate calls through this gateway. It does not cap Firebase, Vercel, requests sent elsewhere or charges above the configured reservation.
5. Set apps/website/public/managed-config.json with the Firebase **web** API key and the fixed HTTPS gateway URL ending in /api/ai. The web key and URL are public configuration. Rebuild the website and Windows installer together, then point the website download button to the managed release asset. Existing v0.1.5 downloads still use the original local-key flow.
6. Before inviting users, verify sign-up, verification email, password reset, sign-in, expiry, disabled/revoked accounts, account changes, concurrent requests near the cap, provider failure and hitting the per-account/global limits. Confirm no upstream request occurs if the transaction is denied or fails. Use separate Firebase data and budgets in staging. Keep preview deployments disabled for paid calls.

The server authorizes verified email accounts and checks token revocation. It checks the session lease and remaining time in a Firestore transaction before calling either provider, while recording reserved provider spend. An optional global cost ledger is checked in that transaction when configured. Failed or timed-out requests retain the reservation because the provider may have billed them. A new account using the same verified email cannot reset its allowance. Multiple distinct email addresses remain possible, so use provider spending controls appropriate to your rollout.

The Windows session holds Firebase tokens in memory and clears them at sign-out or app exit. Managed requests have no direct-key or Replicate fallback. The gateway does not persist prompt, audio, or answer content. Users should be told that playback audio goes to Groq and answer context goes to Replicate and that coding problem lookups go to the relevant publisher.

Checkout and subscription entitlements are a later step. Keep trial and future paid entitlement decisions on the server.

## Unlimited accounts

Set UNLIMITED_USER_UIDS on the gateway project to a comma-separated list of Firebase Authentication User UIDs. Copy each UID from Firebase Console → Authentication → Users. Only an exact matching verified account bypasses the per-account trial cap. Keep this setting on the server.

After changing this variable, redeploy the gateway. In Windows, end the session, sign out, and sign back in to refresh the allowance. The v0.1.12 installer shows Unlimited access. Earlier v0.1.11 installers support unlimited accounts but must be updated to use the time-limited public trial. The website profile shows Unlimited access.

Usage is still recorded in the account ledger. Removing a UID restores the ordinary one-hour cap against that account’s recorded active time. Time used while exempt does not consume the trial. Email verification, request rate controls, provider limits, and any configured shared beta cap continue to apply. Provider charges continue for unlimited accounts.

Transcription is configured for English with language=en and temperature=0 on the gateway and the local-key development path. Continuous speech is uploaded in roughly three-second chunks with a 250 ms overlap. Question completion still waits for the existing speech pause. The gateway runs in Mumbai (bom1), close to the Delhi Firestore database.

Windows v0.1.14 runs bundled RNNoise locally before upload. Playback is converted to mono, cleaned in 10 ms frames, and delivered as 16 kHz PCM. Speech detection controls chunk boundaries and the question-completion clock, so steady noise does not keep the question open. Cleaned audio chunks use a 300 ms silence boundary while the existing longer question pause remains. RNNoise notices ship in the engine assets/rnnoise directory. Résumé/history retrieval now counts document frequencies once per query and produces the same evidence rankings.
